# 学习规则

## 1. 总原则

本仓库服务长期成长，不服务短期表演。

每次学习和开发都要尽量留下：

- 可运行代码
- 清晰笔记
- 错误记录
- 技术决策
- 下一步计划

## 2. AI 使用规则

AI 可以帮助：

- 解释概念
- 拆解任务
- 设计练习
- 审查代码
- 提供调试思路
- 生成初稿
- 对比方案

AI 不应该替代：

- 自己理解代码
- 自己运行验证
- 自己判断方案是否合理
- 自己总结经验
- 自己完成关键练习

每次使用 AI 生成代码后，必须至少能回答：

1. 这段代码解决了什么问题？
2. 输入是什么？
3. 输出是什么？
4. 失败情况有哪些？
5. 我能不能不看答案重写一遍？

## 3. 项目开发规则

每个项目至少包含：

- 项目目标
- 使用方法
- 核心功能
- 当前状态
- 已知问题
- 下一步计划

代码进入 `projects/`。

学习笔记进入 `notes/`。

外部资料和整理文档进入 `docs/`。

规划和学习系统文件进入 `00-Planning/`。

## 4. Git 规则

每次提交前检查：

```powershell
git status
```

提交粒度要清晰：

- 一次提交只做一类事情
- 不把无关修改混在一起
- commit message 要能看懂本次变化

推荐提交格式：

```text
docs: add learning profile
learn: add python function practice
fix: correct leap year logic
refactor: split python basics into functions
```

禁止：

- 不理解代码就提交
- 把 API Key 提交到仓库
- 随意删除历史文件
- 大规模重构但没有说明原因

## 5. 学习记录规则

每次学习后至少记录三件事：

1. 今天学了什么
2. 哪里卡住了
3. 下一步做什么

遇到错误时记录：

- 错误现象
- 错误原因
- 修复方式
- 以后如何避免

做技术选择时记录：

- 选择了什么
- 为什么选择
- 放弃了什么
- 长期影响是什么

## 6. 练习规则

每个知识点至少经历四步：

```text
看懂
-> 跟写
-> 改写
-> 独立重写
```

如果只能看懂，不能独立写出，说明还没有真正掌握。

## 7. 项目难度规则

项目必须略高于当前能力，但不能高太多。

判断标准：

- 70% 内容应该能通过已有知识完成
- 20% 内容需要查资料和思考
- 10% 内容可以借助 AI 和导师指导

如果 50% 以上都看不懂，说明项目过难，需要降级。

## 8. 复盘规则

每周至少做一次复盘：

- 本周完成了什么？
- 哪些能力变强了？
- 哪些问题重复出现？
- 哪些内容需要补课？
- 下周最重要的一个目标是什么？

## 9. 实习导向规则

从现在开始，每个项目都要思考：

- 能不能写进简历？
- 面试官会问什么？
- 我能不能讲清楚技术难点？
- 项目有没有真实使用场景？
- 有没有可展示的运行方式？

不是所有练习都要变成作品，但每个月至少要有一个能沉淀为作品集素材的成果。

## 10. 导师协作规则

向 AI 导师提问时，优先提供：

- 当前目标
- 当前代码或错误
- 已经尝试过的方法
- 希望得到的输出

推荐提问格式：

```text
我的目标：
当前代码：
遇到的问题：
我已经尝试：
请你帮我：
```

导师可以直接指出：

- 学习顺序不合理
- 项目过难或过简单
- 代码质量问题
- 架构风险
- 实习准备方向偏差

目标不是让答案更舒服，而是让工程能力更强。
